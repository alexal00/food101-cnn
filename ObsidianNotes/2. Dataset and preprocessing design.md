# 1. Dataset acquisition
Use an automatic download path, preferably through:
1. Kaggle APi for the linked Food-101 Kaggle dataset.
2. `torchvision.datasets.Food101` if official Food-101 structure is preferred
`torchvision.datasets.Food101` exposes the official train and test splits.

Recommended logic:
```text
Check local dataset path
→ if missing, download dataset
→ extract images
→ verify expected class count
→ verify train/test split metadata
→ generate local dataset index
```
# 2. Official split preservation
Making use of:
```text
official train split → training + internal validation
official test split  → final test only
```
Recommended internal split:
```text
official train split:
    85% train
    15% validation

official test split:
    untouched final evaluation
```

Thus, avoiding using the test set for model selection.

# 3. Image validation
Before training, add a validation pass:
```text
For each image:
	open with PIL
	correct EXIF orientation
	covert to RGB
	verify dimensions
	verify readable pixel content
	log failures
```
Outputs:
```text
data/reports/image_validation_report.csv
data/reports/corrupted_images.txt
```
This prevents that a corrupted image interrupts the log training runs
# 4. Preprocessing
Required preprocessing
```text
EXIF orientation correction
→ RGB conversion
→ resize with padding to 224×224
→ tensor conversion
→ ImageNet normalization
```

ImageNet normalization is appropriate because the transfer-learning models will use ImageNet-pretrained weights. Torchvision provides classification model familias and pretrained weights for image classification, including ResNet, EfficientNet, EfficientNetV2, and ConvNeXt.

# 5. Padding instead of hard cropping
Padding is preferred over hard-cropping since food images often contain discriminative global context: dish shape, plate layout, toppings, side ingredientes, and texture distribution. Hard cropping can remove relevant food regions. paddign preserves the full image context while standarizing input size.
