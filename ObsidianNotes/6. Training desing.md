Use an automatic device selection:
```python
if torch.backends.mps.is_available():
    device = "mps"
elif torch.cuda.is_available():
    device = "cuda"
else:
    device = "cpu"
```

Because local memory is limited, the could supports fallback settings:
```text
batch_size: 16 initially
num_workers: conservative
gradient accumulation: optional
mixed precision: enabled only if stable for the selected backend
```

The transfer-learning schedule is:
```text
Stage 0 — sanity check
    5–10 classes
    1–2 epochs
    verify loss decreases
    verify metrics are computed

Stage 1 — head training
    freeze pretrained backbone
    train classifier head only
    moderate learning rate

Stage 2 — partial fine-tuning
    unfreeze last backbone blocks
    lower learning rate
    monitor validation top-5 accuracy

Stage 3 — full fine-tuning, optional
    unfreeze more layers
    very low learning rate
    use early stopping
```

Staged training is a safer solution since:

|Stage|Reason|
|---|---|
|Sanity check|Detects pipeline bugs before expensive training.|
|Frozen backbone|Fast, stable, low memory, strong initial baseline.|
|Partial unfreeze|Allows Food-101-specific feature adaptation.|
|Full fine-tuning|Can improve final accuracy but increases overfitting and compute cost.|
The selected optimizer is Adam, with the following settings
```yaml
optimizer:
  name: adam
  lr_head: 1.0e-3
  lr_finetune: 1.0e-5
  weight_decay: 1.0e-4
```
AdamW can be use later as a correction is overfitting or poor generalization appears

The scheduler is:
```text
ReduceLROnPlateau
```
Easier to explain than cosine decay. It reduces learning rate when validation performance stops improving.

Possible alternatives are:
* `CosineAnnealingLR`: better for longer, controlled, training but less directly diagnostic

The loss function is: cross-entropy with label smoothing
```python
CrossEntropyLoss(label_smoothing=0.1)
```

Since Food-101 contains noisy training images/labels by design, so label smoothing helps reduce overconfident memorization of noisy samples. The dataset documentation notes that training images are not cleaned and can contain noise or wrong labels.

Class weights should not be enabled by default. Class counts will be computed first, since canonical Food-101 is balanced, loss weighting is probably unnecessary unless the Kaggle subset differs from the canonical.
